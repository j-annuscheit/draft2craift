Step 0

What this tutorial is for

This tutorial is aimed at AI/software developers who are new to the project, but want to get up to a productive level quickly. The goal is not only "what" to do, but "why" each decision (policy, loop, wiring, UI parameter) was set this way.

Core Workflowmindmap_agentic (v3) + graph_agentic
Core Runnermap.seed_from_outline, map.propose_child_nodes, map.validate_candidate_tree
UI ControlUser mode slider for expansion depth

What you will be able to do at the end

  • Implement and register new agents as step runners.
  • Build workflow definitions with loops, guards, overflow paths and fail strategy.
  • Validate candidate outputs first and then commit or discard them.
  • Set policy/profile so that output remains robust and deterministic enough.
  • Pass UI parameters (here: expansion depth) through to Agentic runs.
  • Secure the implementation with tests against regression.

If you start without project knowledge

You don't have to understand the whole project for this tutorial. It is enough if you keep this simple chain in mind: The GUI collects a user request, the service loads definition + profile, the engine executes steps, and a terminal step returns the result to Canvas or Chat.

TermMeaningWhere you see it
WorkflowThe flow graph of a job.data/workflows/definitions/*.toml
RunnerA Python function for exactly one step.shared/services/agentic/workers/**/*.py
ProfileConfiguration for behavior, limits and wiring.data/workflows/profiles/*.toml
ProjectionWhat data a step is officially allowed to see.Sections [projections.*] in the definition
CandidateA proposed new state that has not yet been committed.state._candidates.*

How to read this tutorial

  • Step 1 explains the basic model so that the later files don't seem like a coincidence.
  • Step 2 shows how a single agent step is technically built.
  • Step 3 explains how these steps are connected to a workflow.
  • Step 4 shows how the workflow arrives in Service, Settings and GUI.
  • Step 5 is intended for looking up individual code paths.
  • Step 6 shows the shortest safe sequence for new workflows.
Recommendation: Really follow the pages in this order. The later sections deliberately build on the concepts from steps 1 to 3.
